# Catalog Files Merge Strategy

## Problem

Catalog files (`*.json`) contain test-generated timestamps (`generated_at`, `fetched_at`) that change on each test run, causing merge conflicts when different branches modify the file.

## Solution

We use Git's `merge=ours` strategy (configured in `.gitattributes`) to automatically resolve conflicts by keeping the current branch's version.

### How It Works

- **When merging a PR (branch → main)**: Git keeps main's version (which is "ours" in that merge context)
- **When rebasing/updating branch (main → branch)**: Git keeps the branch's version (which is "ours" in that merge context)

This ensures:
- No manual conflict resolution needed
- Timestamp differences don't cause conflicts
- The file remains functional (catalogs work with any timestamp)

## Configuration

The merge strategy is configured in `.gitattributes`:
```
registry/catalogs/*.json merge=ours
```

## Why Not Update in `make test`?

**We do NOT update catalog files in `make test`** because:

1. **Test artifacts shouldn't be committed**: Tests generate files with temporary paths and timestamps that are environment-specific
2. **Merge strategy handles it**: The `merge=ours` strategy automatically resolves conflicts
3. **Catalogs are optional**: The system works without catalog files - they're metadata only
4. **Tests use separate files**: Tests should use temporary files, not modify committed files

## Best Practices

1. **Don't manually edit catalog files** - They're generated by `dativo connectors sync`
2. **Don't commit test-generated catalogs** - If tests create catalog files, use temporary locations
3. **Regenerate if needed** - After merging, regenerate catalogs if you need fresh metadata:
   ```bash
   dativo connectors sync --catalog-url <url>
   ```

## Alternative Solutions Considered

1. **Custom merge driver**: More complex, requires Python script - unnecessary for this use case
2. **Normalize timestamps**: Would require pre-commit hooks or merge drivers - adds complexity
3. **Ignore in git**: Not viable - catalog files are needed for the system to work
4. **Update in make test**: Not recommended - commits test artifacts
